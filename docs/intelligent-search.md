# PS Intelligent Search + Live Scope

The current shell/router, authenticated catalogue, public catalogue access gate, product cards/details and basket remain authoritative. `current/behaviour/intelligent-search.js` supplies a pure constrained interpreter and ranker; `app.js` resolves only visible current catalogue records and reduces the existing draft basket. Public catalogue access remains gated as before.

Supported commands resolve locally first, preserving keyword typing and category browsing. Unknown descriptions may use the authenticated `/api/interpret-request` endpoint. The endpoint uses AI SDK 7 structured output through Vercel AI Gateway OIDC (`AI_GATEWAY_API_KEY` is optional for external/local runtimes). The default model, `openai/gpt-5.4-nano`, was confirmed in the live Gateway model list on 2026-10-07; `AI_GATEWAY_MODEL` can override it. The endpoint requires a valid token from the existing Supabase project. It never queries catalogue/private sourcing tables or writes database records. Only the description and previous search terms reach the model. Requests are bounded, timed out, and limited to 12 per authenticated user per minute per function instance; this is a local burst guard, not a global billing quota.

The model produces a constrained interpretation, never HTML, pricing, SKUs or database mutations. The client accepts model enhancement only for search/comparison. Customer-requested draft mutations use the local interpreter and existing state. Uncertain additions show a real catalogue-line choice; ambiguous gauze sizes come from current records. Authoritative displayed sizes take precedence over conflicting old record names. A failed/slow model request retains keyword/category browsing and safe local commands.

Scope metadata lives in `state.scopesBySchool`, keyed with the same active-school context as the basket. Existing/retained lines are snapshots excluded from active basket totals. Site counts never multiply quantities. The customer can confirm that quantities are totals across sites. The review drawer displays metadata; submission appends readable scope, units and retained items to the existing order note. No schema changes or autonomous submission. Demo state remains local, does not overwrite live storage, and resets on refresh.

Desktop uses the existing card grid plus a sticky request panel. At narrower widths, a fixed summary opens a request sheet. Three columns remain where content width permits; existing two/one-column behaviour applies at narrower widths. No chatbot or transcript.

Verification: shell, catalogue DOM, general DOM/browser stories, catalogue browser regressions, pure interpreter/API/SDK tests, and the complete requested command sequence at 1440px and 390px. Browser backend transport is mocked and prohibits demo writes. API rejection and SDK structured output are tested separately. An authenticated production model request requires a signed-in customer session and Gateway team access/credits; local deterministic tests are not evidence of a live provider call.
