# PS product-aware search and working scope

The authoritative current shell/router, controlled catalogue, public access gate, product details and existing basket remain in charge. Shop landing search appears before categories and also exists on category pages. Typing debounces result updates without replacing, scrolling or refocusing the input. Input font size is 16px to avoid iOS focus zoom; the narrow-screen request footer hides during typing. Browser tests verify input identity, focus and position on every character; real iPhone keyboard behaviour still requires device verification.

## Product Knowledge Index

`tools/build-product-index.mjs` rebuilds a persistent, deterministic index from all 685 controlled product records as part of `npm run build`. The index is separate from those records and never overwrites them. It contains public display/official names, IDs, category/type, brand/model, specifications, pack, domain concepts, common descriptions, abbreviations, spelling aliases, institutional context, related catalogue IDs and explicitly supplied verified compatibility links. Private commercial/supplier data is excluded. Visibility gates still apply. Runtime CMS changes are enriched again if their public record fingerprint differs from the persisted baseline.

Retrieval combines exact ID/name matches, token frequency weighting, prefix and edit-distance tolerance, synonym concepts and cosine similarity over PS domain-concept vectors, followed by customer-context ranking. These are explicit domain vectors, **not pretrained neural embeddings**. Broader interpretation uses the catalogue-grounded LLM endpoint. Related product IDs are search alternatives, not clinical substitutes. Same-model accessory ranking is useful but never establishes compatibility; verified links require explicit `verifiedCompatibleSkus` data. The present catalogue does not supply that structured link field, so exact compatibility still requires PS verification. Displayed dimensions take precedence over conflicting historical official names.

## Session and model enhancement

Working memory is scoped to the active institution and cleared on logout/refresh. It retains selected actual products, recent searches, previous intent and dimensions while visible query text resets on navigation/history. Basket family lines and exact option snapshots also contribute context. Delivery location and order type remain in existing scope metadata. Reference commands resolve against actual selected/request lines. Cheaper queries do not imply a price comparison without controlled prices. Site counts never multiply quantities.

Typing and local matches are immediate. Submission can enhance search/comparison asynchronously through `/api/interpret-request`; it never waits to show local results or replaces the input when a model response arrives. A sequence guard prevents older responses overriding newer typing/navigation. AI SDK 7 structured output uses Vercel AI Gateway OIDC; the default model is `openai/gpt-5.4-nano` (confirmed in the Gateway model list 2026-10-07). The endpoint verifies an existing Supabase bearer token and supplies only the public controlled index plus bounded session context. Model-selected IDs are intersected with that index on the server and with current visible records in the client. The model cannot mutate baskets/database records. It cannot invent displayed products, prices, stock, regulatory status or compatibility.

The API is timed out and has a 12/user/minute function-instance burst guard, not a global billing quota. Slow/failed/unavailable Gateway enhancement leaves local retrieval and category browsing functional. No new database tables, schema, production data or privileged keys. Demo request/quote actions stay local. Scope metadata continues to use existing order notes.

## Verification

Pure tests cover all requested typo/descriptive examples, selected glucometer → Guide strips → lancets, real record IDs, verified-link fixtures and invalid model IDs. Browser stories at 1440/390px cover shop prominence, per-character input stability, commands/quantities/references, request handoff, demo isolation and refresh. A mocked authenticated model response verifies asynchronous ranking and rejection of invented IDs/stale responses. Catalogue layout/history tests run at 390/768/1024/1440px; shell, catalogue, public routes, Workshop and portal regressions also run.

Authenticated live-provider inference has **not** been verified: it requires a customer session plus Gateway team access/credits. Mocked structured-output tests and successful deployment are not evidence that those live credentials/credits work. No production records were modified during verification.
